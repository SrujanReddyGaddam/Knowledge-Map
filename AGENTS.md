# AGENTS.md: Knowledge Map

Instructions for coding agents (Claude Code, Codex, Cursor, etc.) working in this repo, including when a user says "set this up for my vault".

## What this is
A local web app that shows one or more Obsidian vaults (folders of markdown notes with `[[wikilinks]]`) as an interactive 3D map, with a side panel that renders the selected note. It is read-only on the vaults, with one exception: the note Delete button moves a file to the OS Trash. Nothing is uploaded anywhere; all data stays on the user's machine.

Stack: Vite + React + TypeScript, three.js with d3-force-3d (graph), gsap, marked (markdown), @excalidraw/excalidraw (drawings, lazy loaded), WebAudio (click sounds).

## Setting it up for a user (do this when asked to "set it up")
**Follow `.claude/skills/setup-knowledge-map/SKILL.md`** (Claude Code loads it as the `setup-knowledge-map` skill; other agents: read the file). It interviews the user, finds their vaults, scans for secrets, creates or adopts a vault from `starter-vault/` with `scripts/new-vault.mjs`, writes `config.json`, installs, verifies, and offers to organize and sanitize existing notes. The rest of this section is the reference it relies on.

Prerequisites: Node `^20.19.0 || >=22.12.0` and npm (the vault scripts need 22.18+ for TypeScript type stripping). Check with `node -v`.

Ask the user these questions (use sensible defaults if they say "you decide", and tell them which calls you made):
1. **Vault path(s):** absolute path to each Obsidian vault folder (the folder that contains `.obsidian/`). One or several.
2. **Names:** display name per vault (default: folder name).
3. **Exclude:** files to leave out, relative to the vault root. Always ask about secrets (tokens, `.env`-like notes, credentials) and meta files like `README.md`. Entries are an exact path (`"README.md"`), a folder ending in `/` (`"private/"`), or a glob (`"**/_templates/**"`, `"drafts/*.md"`). Dot-folders are always skipped.
4. **rootSection:** label for notes sitting in the vault root (default `General`). Top-level folders become "sections" in the map.
5. **How to run:** (a) on demand with `npm run dev`, or (b) always-on at login. Always-on is macOS only (launchd), see below. On Linux/Windows suggest a systemd unit / Task Scheduler running `node node_modules/vite/bin/vite.js --port 7777` from the repo root, or just on demand.
6. **Look and feel (optional):** palette (`paper`, `sage` default, `clay`, `ocean`, `dusk`; users can also switch in the UI), sound off by default.

Then:
```
cp config.example.json config.json      # never commit config.json
# edit config.json from the answers above
npm install
npm run dev                              # http://localhost:7777  (also http://knowledge.localhost:7777)
```
Always-on on macOS: `scripts/install-launchd.sh` (add `--label com.<name>.knowledge-map` to choose the service name, `--print` to preview, `--uninstall` to remove). It uses the `node` on the current PATH, so run it from a shell where `node -v` shows the version the user wants. Restart after editing `config.json` or the server-side files (see Updating below):
`launchctl kickstart -k gui/$(id -u)/<label>`. Logs: `~/Library/Logs/knowledge-map.log`.

Verify before telling the user it works: server returns 200, the startup log line `[vault] <names>: N notes, M links, K unresolved` shows the expected counts (0 notes means a wrong path or a macOS permission problem), and open the page (screenshot if you can drive a browser).

## Updating an existing install (do this when told "there are updates to the repo", "update the app", "pull the latest")
Work out what the update needs from what actually changed, run only that, and report. Never touch the user's vaults or `config.json` while updating.

1. **Before:** in the repo folder, note the current commit (`OLD=$(git rev-parse HEAD)`) and, if the app is running, the current `[vault] ...: N notes, M links, K unresolved` line (last one in the log, e.g. `~/Library/Logs/knowledge-map.log` for launchd). Run `git status`: `config.json`, `PLAN.md` and `TODO.md` are git-ignored and never conflict. If tracked files were edited locally, show the user and ask before `git stash` (pop it after the pull and report any conflict instead of resolving it by guessing).
2. **Pull:** `git pull --ff-only`. If that refuses (local commits or a diverged branch), stop and ask the user. Then re-read this file: the update may have changed these instructions.
3. **Decide from the diff** (`git diff --name-only $OLD HEAD`, and `git log --oneline $OLD..HEAD` for the summary):

| Changed | Do |
|---|---|
| `package.json` or `package-lock.json` | `npm install`. Check `node -v` against the prerequisites above first; if Node is too old, stop and tell the user. |
| `vite.config.ts`, `vault-plugin.ts`, `vault-load.ts`, `frontmatter.ts`, `rename-links.ts`, `append-text.ts`, `projects.ts` (the server side) | Restart the server: `launchctl kickstart -k gui/$(id -u)/<label>` for always-on (find the label with `launchctl list \| grep knowledge-map`), else stop and start `npm run dev`. Restarting when unsure is safe. |
| only `src/` files | Nothing to run; the dev server hot-reloads. The user reloads the page once (Cmd+R, or the reload button in the top right). |
| `mcp-server.ts`, any root `.ts` file, or `src/*.ts` | If the user registered the MCP server (`claude mcp list` shows `knowledge-map`), it runs the old code until Claude Code restarts or the user reconnects it with `/mcp`. Tell them. |
| `config.example.json` | Compare it with their `config.json` and tell the user about new options. Never edit `config.json` without asking; back it up first if they say yes. |
| `scripts/install-launchd.sh` | Preview with `--print` and the user's label; reinstall only if the generated service differs and the user agrees. |
| `starter-vault/` | Their vaults are not updated automatically, and that is right. List what is new (skills in `starter-vault/.claude/skills/`, templates, README rules). Offer to copy a skill folder that their vault does not have yet (`cp -R starter-vault/.claude/skills/<skill> <vault>/.claude/skills/`); never overwrite their files, and do not run `new-vault.mjs --adopt` for this (with an existing README it adds a second rules file, `VAULT-RULES.md`). Rule or template changes are offered as a short summary for the user to accept, not applied. |
| `.claude/skills/` in the repo | Agents pick it up on the next start; nothing to run. |

4. **Verify:** `npx tsc --noEmit` passes, the server returns 200, and after a restart the log line shows the same counts as before (a drop to 0 notes means a path or macOS permission problem, see Conventions and gotchas). Open the page if you can drive a browser.
5. **Report** in a few lines: the commits pulled (from `git log --oneline`), what you ran and why, what the user still has to do (reload the page, reconnect MCP, optional vault skills), and what they will notice (from the commit messages).

## Starter vault and vault skills
`starter-vault/` is the template for a new, organized work vault: rules (`README.md`, with `{{PLACEHOLDERS}}` filled in by the script), the 16 note templates, an `index.md` hub, fictional `acme` example notes, and agent skills in `starter-vault/.claude/skills/` (`organize-vault` for the one-time cleanup and sanitizing of existing notes, `triage-inbox`, `lint-vault`, `distill`, `harvest-project`). `node scripts/new-vault.mjs <path> [--adopt] [--config] ...` copies it (see the header of the script for flags); `--adopt` adds only the scaffold to an existing vault and never overwrites a file. Keep everything in `starter-vault/` free of real names, customers and paths: it ships to everyone.

## config.json
```json
{ "vaults": [ { "name": "my-vault", "path": "/abs/path", "exclude": ["README.md"], "rootSection": "General", "writable": false } ] }
```
`writable` (default `false`) lets the app edit that vault's markdown notes and create new ones. Ask the user per vault; leave iCloud-synced vaults and anything sensitive read-only unless they opt in.

Optional per vault:
- `sectionDepth`: folders whose sections go deeper, e.g. `{ "projects": 2, "knowledge": 2 }` turns `projects/acme/x/y.md` into section `projects/acme`.
- `lint: true`: check notes against the vault schema in the Health tab (missing `type`/`summary`/`sensitivity`, `current` notes whose `source_fetched` is over 90 days old, inbox items over 7 days, notes not linked to a `type: hub` note). `inbox/`, `sources/`, `archive/` and `journal/` get lighter rules.
- `sensitivity`: default for notes without one (e.g. `"personal"` for a personal vault).

Frontmatter fields the app understands beyond title/tags/summary/status/source: `type`, `customer`, `project`, `component` (optional part of a project, listed on the project hub under `## Components`), `sensitivity` (`public | internal | customer-confidential | personal`), plus any other key for `key:value` search. Templates for New note are the `.md` files in `<vault>/_templates/` (exclude that folder); template frontmatter may hold `km_folder:` (default folder) and `km_dated: true` (file name starts with the date), both removed from the new note; placeholders `{{title}}` `{{date}}`.

`config.json` is git-ignored because it holds local paths. Only `config.example.json` is committed. Server restart is required after changing it.

## Conventions and gotchas
- **Port:** defaults to 7777 and is read from env `KM_PORT` by both `vite.config.ts` and `vault-plugin.ts` (Host and Origin allowlists). The launchd script still passes `--port 7777`; if you change the port also set `KM_PORT` there. Other env: `KM_CONFIG` (alternate config file) and `KM_BACKUP_DIR` (default `~/.knowledge-map/backups`). Use all three to run a throwaway instance for tests beside a real one.
- **Never commit** `config.json`, vault content, screenshots of real vaults, or anything from a user's notes. Vaults can contain customer or personal data. Do not paste note content into issues, commits or logs.
- **Write paths are guarded; keep them that way.** `vault-plugin.ts` exposes `GET /api/session` (per-start token), `GET /api/raw?id=` (exact file text + sha256), `POST /api/save`, `GET /api/history?id=` and `GET /api/version?id=&name=` (saved versions; the name must match the timestamp pattern and is never used as a path), `POST /api/rename` (rename or move inside one vault: `dryRun` returns a plan with a hash, applying must send that hash back; backs up every touched file, rewrites `[[links]]`, `![[embeds]]` and relative `.md` links in other writable notes atomically, skips code blocks, rolls back on failure, moves the note's history along, refuses name clashes; links in read-only vaults are only warned about and need an explicit ack), `GET /api/templates?vault=` (writable vaults only, `_templates/*.md`, max 64 KB each), `POST /api/create` (`{vault, path, text}`: writable vault, same name rules as rename, realpath of the deepest existing folder must be inside the vault, refuses existing files and file names that already exist anywhere in the vault, claims the name with an exclusive create and then renames a flushed temp file over it; do not switch to hard links, the macOS watcher misses them), `POST /api/append` (`{vault, path, heading, line, init?}`: one line, no newlines, under a heading; the file must be a note in the map or one this server created in the last 30 s, else it is created from `init` with the same rules as create; backup first, atomic write), `POST /api/attach` (`{id, ext, data}` base64: png/jpg/gif/webp checked by magic bytes, 10 MB max, saved beside a writable note as `<note>-<timestamp>.<ext>` with an exclusive create, never replacing a file), `GET /api/projects` (read-only), `GET /api/gitlog?vault=&since=&until=` (read-only: dates must be YYYY-MM-DD, git runs with execFile and fixed arguments, only for configured vaults with a `.git`, file paths filtered like the loader: markdown, no dot-folders, the vault's exclude list), `POST /api/delete`. Restoring a version is just a normal save of the old text, so the current text is backed up first. Every call goes through `guard()`: Host allowlist (DNS rebinding), `X-KM: 1` header (forces a CORS preflight we never answer), and for writes our own Origin plus the token. Save works on the raw file text (frontmatter and CRLF untouched), returns 409 with the current text if the file changed since load (hash compare), writes a backup first to `KM_BACKUP_DIR/<vault>/<path>.history/<timestamp>.md` (keeps 50 versions / 90 days, always the newest), then writes atomically (dotfile temp in the same folder, fsync, rename). Ids map to files server-side and must resolve inside a `writable` vault (realpath checked, so symlinks cannot escape); only `.md`, never drawings, max 2 MB. Do not loosen any of this, and test any new write path on a throwaway instance (scratch vault, `KM_PORT`/`KM_CONFIG`/`KM_BACKUP_DIR`), never on the user's real vaults.
- **Editor behavior to preserve:** it edits the exact file text; CRLF files are shown as LF and converted back on save (browsers normalize textarea newlines), files with mixed endings are refused; own saves do not reload the page mid-edit (server sends `km:self-write`, the page refreshes when the editor closes) while external changes still reload; an unsaved draft is kept in sessionStorage (`kmDraft`) and reopens after a reload, with a conflict banner if the file changed on disk meanwhile; leaving the note or closing the tab with unsaved changes asks first; the default editor is the rich one (`RichText.tsx`: it only styles and hides syntax marks, the document is always the exact markdown, so saving never reformats; "Source mode" in the toolbar switches to a plain textarea, remembered in localStorage `editorMode`); typing `[[` opens a note-name suggestion list (arrows, Enter/Tab accept, first Esc only closes the list) and inserts the bare file name plus `]]`. Key handlers in the editor must stop Esc from reaching the page-level handler in `App.tsx`.
- Excluded files never reach the browser. When a user names a secret file, add it to `exclude` and confirm the note count dropped.
- macOS: background processes may be blocked from `~/Documents`, `~/Desktop` or iCloud folders. Symptom: vault shows 0 notes or `vault not readable` in the log. Fix: grant the `node` binary Full Disk Access, then restart. iCloud notes not yet downloaded appear as `.icloud` stubs and are skipped.
- Supported content: markdown with frontmatter (`title`, `tags`, `summary`, `type`, `status`, `related`, `source`), wikilinks, `![[image]]`, `[x](./y.md)` links, callouts, Excalidraw (`*.excalidraw.md` and `*.excalidraw`). Not supported: `.canvas`, `.base`, PDF embeds, executing Dataview (the block is shown with a "not run" label).
- Hash links (`#note-id`) are read once at load; changing only the hash in a running page does not open the note.
- **Safe mode** (shield button, `?safe=1|0`, localStorage `safeMode`): fails closed, a note without `sensitivity` is hidden. In visible notes, `[[links]]` to hidden notes (body, summary, source, frontmatter values) are shown as "(hidden note)", so a customer-first file name never appears on screen; display only, the editor still works on the exact file text. Toggling reloads the page so module-level indexes are rebuilt from the filtered data.
- Note titles fall back to the first `# heading` outside code blocks.
- `window.__km` is a debug hook exposing graph nodes for browser tests.

## Checks
- Focus mode (canvas button, target icon): while on, every selection (map, search, Browse, links) becomes the focus; Esc turns it off and clears the focus. Export PDF uses the browser print dialog with `@media print` rules in `styles.css` that show only the note body on white.
- `npx tsc --noEmit` (or `npm run build`, which also type-checks) must pass.
- There is no test suite. UI changes are verified by loading the page in a real browser (headless Chrome needs `--enable-unsafe-swiftshader` for WebGL) and looking at a screenshot.
- URL params for reproducible screenshots: `?theme=light|dark` `?palette=` `?zoom=` `?q=` `?vault=A,B` `?mode=dim|hide` `?filter` `?info` `?sound` `?safe=1|0` `?view=today|tasks|cockpit|week|circles` `&customer=` `&project=` `&component=` `?capture=1`, and `#<note-id>`. Search operators include any frontmatter key: `type:bug customer:acme -status:stale`.
